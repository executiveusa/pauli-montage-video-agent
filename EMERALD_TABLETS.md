# YAPPY-CLIPZ Emerald Tablets

This file is the repository constitution for YAPPY-CLIPZ. Lower-level prompts, agent preferences, tasks, and implementation choices may not override it.

## I — Verify It Before Everything

Do not claim a capability, deployment, test result, integration, migration, or production state without evidence. Prefer deterministic verification over confidence or inference.

## II — Cash Before More Code

Prioritize work that supports a defined customer, problem, offer, delivery path, validated learning, or required platform infrastructure for the active commercial product. Do not create repositories, frameworks, or infrastructure merely because they are novel.

## III — Owner Sovereignty

The owner must control repositories, domains, hosting, databases, exports, provider choice, models, recovery, and operational documentation. Customer retention must come from value, not manufactured lock-in.

## IV — Reuse Before Creation

Before adding a component, service, schema, skill, integration, dependency, or repository:

1. search the current repository;
2. search approved shared repositories and skills;
3. identify existing conventions;
4. extend existing capability when safe;
5. document what a new dependency replaces and its removal path.

## V — Bounded Slices

Every implementation task must have one objective, likely files/services, dependencies, acceptance criteria, verification, evidence, prohibited changes, and rollback considerations. Complete and verify one bounded slice before expanding scope.

## VI — Safe Autonomous Execution

Agents operate in isolated branches/worktrees or sandboxes. They may not weaken required checks, bypass protected main, hide blockers, silently change accepted requirements, or perform irreversible high-risk actions without the required approval.

## VII — Evidence Before Merge

A phase merges only when its accepted specification, tests, build, security checks, review findings, rollback receipt, user-facing verification where applicable, and post-merge plan are satisfied. Merge method is squash only for GRINIONS phases.

## VIII — Honest Product Claims

Marketing and documentation must distinguish working, beta, planned, paid-provider-dependent, and local/GPU-dependent capabilities. Do not claim perfect consistency, perfect lip sync, unlimited inference, or studio-quality parity without repeatable evidence.

## IX — Human and Documentary Integrity

Identity/voice cloning requires authorization. Documentary and real-footage workflows preserve source provenance, quotes, timecodes, meaning, releases, and disclosure of synthetic reenactments where appropriate.

## X — Recoverability

Every consequential phase must capture baseline state and rollback instructions before merge. Destructive database rollback must never run automatically when valid production data could be lost.
