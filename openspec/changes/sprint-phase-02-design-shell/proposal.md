# Proposal: Sprint Phase 2 design system and shell

## Why

The Studio already has real project and editor routes, but shared UI states, focus behavior, and mobile shell behavior are fragmented. Later sprint phases need a stable accessible foundation.

## What changes

- establish reusable visual tokens and state/dialog primitives
- add skip navigation, current-page semantics, focus rings, and touch targets
- define desktop, tablet, mobile, and reduced-motion behavior
- prove shell controls resolve to real repository routes

## Impact

The change is presentation-only and preserves project, authentication, provider, timeline, and persistence contracts.
