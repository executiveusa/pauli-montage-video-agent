Planning audit / Phase 05 baseline

Architecture audit

YAPPY-CLIPZ has a strong contract-first base, a shared service layer, three current interfaces, a neutral timeline editor, and a verified production shell. The next risk is not missing features; it is multiplying features before transport parity, hosted identity, durable jobs, and ICM traceability become machine-enforced.

Scope: architecture, agent interoperability, ICM, security boundaries, and release sequencing. This document makes no visual-design score because no new screenshot-based visual audit was performed.

Evidence boundary

This planning audit is grounded in repository code, merged Phase 05 evidence, production route responses, and the uploaded ICM/design-audit methods. A visual UI audit is deferred to the dedicated product UX phase, where desktop/tablet/mobile screenshots, keyboard checks, link tests, and accessibility evidence are mandatory.

Self-evident agent use

An arbitrary agent currently needs repository-specific knowledge to find commands/tools. Capability discovery and exact schemas must make the system self-explanatory.

Obvious next action

Agents need stable action IDs, risk, approvals, cost, sync/job behavior, and errors before they execute.

Predictable navigation

CLI, API, and MCP should expose the same conceptual action map rather than transport-specific naming drift.

Error recovery

Version conflict exists for timelines, but standardized problems, retryability, jobs, cancellation, and resume must become universal.

Architecture anti-slop findings

  • Do not add provider-specific buttons/tools before the neutral action contract.
  • Do not call separate Python functions directly from each transport.
  • Do not use ICM folders as a second database.
  • Do not treat a caller tenant header as hosted authentication.
  • Do not claim “any agent can call it” until discovery and parity tests prove it.
  • Do not build generation before jobs, approvals, costs, provenance, and idempotency.
